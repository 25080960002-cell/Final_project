1. Analisis Sistem Informasi

1.1 Latar belakang

Kelompok tani/gapoktan umumnya mencatat kegiatan pertanian secara manual (buku tulis, WhatsApp, dan ingatan pengurus). Data lahan, komoditas, anggota, dan hasil panen terserak dan cepat hilang, sehingga laporan ke penyuluh/dinas selalu memakan waktu dan keputusan musim berikutnya dilakukan tanpa dasar data. MAPAN dibangun sebagai sistem informasi web untuk menyatukan data tersebut dalam satu ruang kerja organisasi.

1.2 Tujuan sistem

  1. Menjadikan satu sumber data tunggal untuk lahan, anggota, dan kegiatan.
  2. Menghitung ringkasan (KPI): jumlah lahan, luas total, jumlah dan progres kegiatan.
  3. Memisahkan hak akses: administrator, manajer, petani, penyuluh (baca saja).
  4. Menghasilkan laporan siap unduh (CSV) untuk pelaporan organisasi/dinas.

1.3 Kebutuhan data

KebutuhanData yang dibutuhkan
Identitas organisasi & anggotaOrganisasi, pengguna, keanggotaan dengan peran
Inventaris lahanNama lahan, luas, status kesehatan, komoditas, petani pengelola
Kegiatan lapanganCatatan aktivitas/tugas/panen/scan, tanggal, progres
Master produkKomoditas, kategori, benchmark produktivitas (ton/ha)

2. Perancangan ERD

Tahap ini mengidentifikasi entitas (objek data utama), atributnya, kunci utama (primary key), serta relasi antar entitas. Enam entitas berikut dipilih sebagai subset nyata dari database MAPAN: hanya bagian yang paling mewakili fungsi utama sistem yang diambil, agar memenuhi ketentuan minimal lima tabel berelasi tanpa melepas konteks proyek.

4. Implementasi Database — SQL DDL

Skrip lengkap: mapan-tugas1.sql (file terlampir; di bawah cuplikannya). Database dibuat terpisah agar aman dan bisa diulang:

CREATE DATABASE mapan_tugas1 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE mapan_tugas1;

CREATE TABLE commodities (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  name            VARCHAR(80)  NOT NULL,
  category        ENUM('pangan','hortikultura','perkebunan') NOT NULL,
  benchmark_yield DECIMAL(6,2) NOT NULL,
  created_at      TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  name          VARCHAR(100) NOT NULL,
  email         VARCHAR(150) NOT NULL UNIQUE,
  phone         VARCHAR(20)  NULL,
  password_hash CHAR(60)     NOT NULL,
  created_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE organizations (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  name       VARCHAR(150) NOT NULL,
  regency    VARCHAR(100) NOT NULL DEFAULT 'Kab. Semarang',
  active     TINYINT(1)   NOT NULL DEFAULT 1,
  created_at TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE organization_members (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  organization_id INT NOT NULL,
  user_id         INT NOT NULL,
  role            ENUM('administrator','manager','farmer','extension_officer') NOT NULL,
  joined_at       TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_member (organization_id, user_id),
  FOREIGN KEY (organization_id) REFERENCES organizations (id),
  FOREIGN KEY (user_id)         REFERENCES users (id)
);

CREATE TABLE plots (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  organization_id INT NOT NULL,
  commodity_id    INT NOT NULL,
  managed_by      INT NULL,
  name            VARCHAR(120) NOT NULL,
  area_hectares   DECIMAL(8,3) NOT NULL,
  status          ENUM('sehat','waspada','kritis') NOT NULL DEFAULT 'sehat',
  FOREIGN KEY (organization_id) REFERENCES organizations (id),
  FOREIGN KEY (commodity_id)    REFERENCES commodities (id),
  FOREIGN KEY (managed_by)      REFERENCES users (id)
);

CREATE TABLE organization_records (
  id               INT AUTO_INCREMENT PRIMARY KEY,
  organization_id  INT NOT NULL,
  plot_id          INT NULL,
  author_id        INT NOT NULL,
  record_type      ENUM('activity','task','harvest','scan') NOT NULL,
  title            VARCHAR(160) NOT NULL,
  occurred_on      DATE         NOT NULL,
  progress_percent TINYINT      NOT NULL DEFAULT 0,
  FOREIGN KEY (organization_id) REFERENCES organizations (id),
  FOREIGN KEY (plot_id)         REFERENCES plots (id),
  FOREIGN KEY (author_id)       REFERENCES users (id)
);

Q4a — Merekapitulasi (GROUP BY + COUNT + SUM)

SELECT o.name AS organisasi, COUNT(*) AS jumlah_lahan,
       SUM(p.area_hectares) AS total_luas_ha

JOIN organizations o ON o.id = p.organization_id

Q4d — (bonus) rata-rata progres per komoditas (3 tabel + AVG)

SELECT c.name AS komoditas, COUNT(r.id) AS jumlah_catatan,
       ROUND(AVG(r.progress_percent), 1) AS rata_progres
FROM organization_records r
LEFT JOIN plots p ON p.id = r.plot_id
JOIN commodities c ON c.id = p.commodity_id
GROUP BY c.name
ORDER BY rata_progres DESC;

Kesimpulan

  • Sistem informasi MAPAN direpresentasikan sebagai 6 tabel berelasi (≥ syarat 5 tabel) dengan relasi master-detail (organisasi→lahan→catatan) dan N:N (anggota organisasi).
  • DDL/DML tereksekusi nyata pada MySQL 8.4.3: exit 0 tanpa ERROR; seluruh tabel terisi ≥ 5 baris data simulasi; UPDATE/DELETE terbukti mengubah/menghapus data.
  • 8 query pengujian menampilkan, menggabungkan (JOIN 2–3 tabel), memfilter (WHERE), dan merekapitulasi (GROUP BY + COUNT/SUM/AVG) data sesuai kebutuhan sistem.
